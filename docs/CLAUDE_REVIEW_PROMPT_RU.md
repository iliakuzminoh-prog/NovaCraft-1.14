# Задание для независимого аудита NovaCraft

Дата: 27 ноября 2026 года  
Рабочая ветка: nova/refined-interface  
Базовая ветка: main — не изменять и не сливать без отдельного разрешения.

## Цель проверки

Провести независимый технический и визуальный аудит NovaCraft 1.14 как Windows-лаунчера Minecraft Java Edition. Не считать README, контракт или сообщения разработчика доказательством. Проверять реализацию непосредственно по исходникам, тестам, CI и, когда возможно, по реальному запуску.

Визуальный комплект из восьми экранов передан отдельно в архиве NovaCraft-visual-acceptance-references.zip. Это дизайн-эталоны, а не скриншоты работающей программы.

## Обязательный принцип

Не писать «всё готово», «идеально», «без ошибок» или «полностью безопасно», если это не подтверждено конкретным тестом. Каждое замечание снабжать путём к файлу, строками и воспроизводимым сценарием. Отдельно указывать, что невозможно проверить без Windows-машины, Minecraft-файлов, API-ключа или GPU.

## Проверить в первую очередь

### 1. Изоляция сборок

- Каждая сборка должна иметь отдельный GameDirectory.
- Переключатель сверху должен менять профиль, путь, версию и загрузчик.
- Моды, шейдеры, ресурс-паки, конфиги и datapacks не должны попадать в соседний профиль.
- Datapack должен устанавливаться только в мир внутри saves активной сборки.
- Удаление карточки сборки не должно удалять папку, миры, моды или пользовательские файлы.
- Миграция старых SavedBuilds должна сохранять прежнюю основную папку игры и назначать старым именованным профилям отдельные пути.
- Попробовать сценарии с одинаковыми путями, отсутствующей папкой, недоступным диском, некорректным JSON и сменой активного профиля.

### 2. Modrinth

- Импорт .mrpack должен читать modrinth.index.json, версию Minecraft, загрузчик, список файлов, SHA-512 и overrides.
- Проверить выбор только HTTPS cdn.modrinth.com, проверку конечного адреса после редиректа и запрет path traversal.
- Проверить лимиты размера, повторяющиеся пути, архивы с неверной структурой и отмену при ошибке хеша.
- Проверить, что импорт создаёт новую изолированную сборку и не перезаписывает папку пользователя.
- Отдельно проверить datapack facet all_project_types:datapack по действующей документации Modrinth.

### 3. CurseForge и Forge

- CurseForge ZIP должен читать manifest.json, Minecraft version, конкретный loader ID/version, обязательные projectID/fileID и папку overrides.
- API-ключ пользователь вводит сам; он не должен попадать в settings.json, логи, crash dump, URL или сообщения об ошибках.
- Ключ нельзя пересылать за пределы официального API/CDN.
- Файлы должны проверяться по SHA-1, JAR/ZIP-сигнатуре и лимитам размера.
- Не обходить авторские ограничения на стороннюю загрузку.
- Проверить, что выбранная точная версия Forge передаётся Forge installer, и что после установки Forge дополнительно проверяются файлы Minecraft через CmlLib.
- Встроенный живой каталог CurseForge и импорт NeoForge не заявлять реализованными, если их нет в коде.

### 4. Разрешение экрана и DPI

- По умолчанию параметр запуска должен получать реальные размеры основного Windows-монитора в момент запуска.
- Ручные Width/Height должны работать только в ручном режиме.
- Проверить несколько мониторов, разные DPI и нестандартные разрешения.
- Не подставлять в вывод предполагаемое разрешение пользователя.

### 5. Очередь загрузок

- У каждой задачи должны быть источник, файл, целевая сборка, прогресс и отдельный статус.
- Modrinth-прогресс должен отражать реальный поток байтов и контроль SHA-512.
- CmlLib/Forge должны использовать ByteProgress, а не тяжёлый FileProgress-обработчик на тысячи вызовов.
- Проверить, что обновление прогресса не перестраивает весь список элементов и не блокирует UI.
- Проверить корректное состояние ошибки и отсутствие ложной отметки «Установлено», если загрузка не завершилась.
- Пауза, отмена, возобновление и сохранение истории пока не считать реализованными без соответствующего кода.

### 6. Внешний вид и доступность

Сравнивать реальные экраны с восьмью визуальными эталонами по отдельности:

1. Главная.
2. Сборки.
3. Каталог модов.
4. Загрузки.
5. Ресурс-паки и шейдеры.
6. Скины.
7. Музыка.
8. Настройки и диагностика.

Проверить окно на минимальном размере, стандартном размере и развёрнутом режиме. Составить таблицу несовпадений: геометрия, цвета, типографика, отступы, переполнение, hover/focus/disabled, пустые состояния, загрузка, ошибка. Декоративная картинка не может заменять рабочий элемент.

### 7. Системная безопасность

- Убедиться, что нет автозапуска, скрытых служб, изменений реестра, отключения Windows Defender или загрузки драйверов без явного согласия.
- Не считать совпадающий хеш доказательством безопасности стороннего мода.
- Проверить обработку внешних URI, архивов, путей и файлов с неожиданным содержимым.
- Проверить, что диагностические логи не содержат API-ключи или токены.

## Обязательный формат результата

Для каждой найденной проблемы:

- Severity: Critical / High / Medium / Low.
- Файл и строки: точные пути и номера строк.
- Сценарий: минимальные шаги воспроизведения.
- Причина: объяснить по коду, а не предполагать.
- Исправление: минимальный конкретный patch-план.
- Тест: как подтвердить исправление.

В конце дать отдельные оценки:

- Компиляция и тесты.
- Изоляция сборок.
- Modrinth.
- CurseForge.
- Forge exact version.
- Монитор/DPI.
- Загрузки и UI responsiveness.
- Визуальное совпадение.
- Безопасность.
- Реальный запуск Minecraft.

Не ставить общую оценку «готово», пока не перечислены непроверенные сценарии. Не менять main, не публиковать релиз и не удалять пользовательские данные.
