# NovaCraft ↔ NovaBoost — проект интеграции

## 1. Ответственность программ

**NovaBoost** — отдельный Java/Fabric мод. Он выполняет оптимизации только внутри клиента Minecraft.

**NovaCraft** — Windows-лаунчер. Он не реализует FPS-алгоритмы, а управляет версиями, сборками, установкой и состоянием модов.

Разделение сохраняет независимость: мод можно вручную положить в `mods`, а лаунчер не должен быть обязателен для его работы.

## 2. Модель установки

Все действия относятся только к активной `BuildProfile.GameDirectory`.

Перед установкой лаунчер проверяет:

1. Minecraft ровно 1.21.11 и loader Fabric.
2. Существование активной папки сборки и отсутствие reparse-point на пути.
3. Наличие свободного имени `mods/NovaBoost.jar`.
4. Отсутствие другого активного JAR с Fabric mod ID `novaboost`.
5. HTTPS при скачивании, ограничение размера, SHA-256 и ZIP-структуру.
6. `fabric.mod.json`: id, version, environment=client, minecraft, fabricloader и java.

Скачивание сначала идёт во временный файл внутри папки `mods`, затем проверяется и атомарно переносится на финальное имя. Существующие JAR не заменяются и не удаляются.

**SHA-256 sidecar проверяет целостность скачивания**, но сам по себе не доказывает происхождение файла, если злоумышленник может заменить и JAR, и sidecar. Следующий уровень защиты — проверяемая подпись/attestation релизной сборки.

## 3. Каналы релизов

- **Stable** — только проверенные версии с ручной проверкой Minecraft и модпаков.
- **Preview** — сборки из ветки разработки, помеченные как предварительные.
- Launcher никогда не должен называть preview-релиз стабильным.
- Проверка обновлений выполняется по явному действию пользователя; автообновление без подтверждения не включается.
- При обновлении старая версия не удаляется до проверки новой. В отдельной задаче нужно добавить backup/rollback для контролируемой замены NovaBoost.

Текущий тег `novaboost-latest` — prerelease/nightly. Он не является стабильным релизом.

## 4. Страница NovaBoost в лаунчере

На одной странице показываются:

- состояние: не установлен / включён / отключён / несовместим;
- установленная версия и версия доступного релиза;
- активная сборка и путь папки `mods`;
- совместимость: Minecraft, Fabric Loader и Java;
- размер JAR и результат проверки SHA-256;
- выбранный профиль производительности;
- короткое описание каждого активного модуля и список исключений;
- локальный лог NovaBoost, если он присутствует.

Основные действия:

- установить;
- проверить обновление;
- отключить / включить существующий JAR через безопасное переименование;
- открыть папку активной сборки;
- показать диагностику.

Ни одно действие не должно затрагивать другие сборки пользователя.

## 5. Безопасность

- Нет автозагрузки Windows, служб, драйверов и реестровых изменений.
- Нет отправки телеметрии.
- Нет запуска команд из скачанного JAR или конфигурации.
- Перед заменой версии — проверка ID, версии, Minecraft target и SHA-256.
- Если файл уже существует и не совпадает — остановить операцию, не затирать его.
- Все ошибки установки отображаются понятным сообщением и записываются локально.

## 6. CI / Release pipeline

Для NovaBoost:

1. Проверка Gradle wrapper.
2. Сборочная JDK 25 (текущий Fabric Loom требует её), байткод `--release 21`.
3. `clean test build`.
4. Проверка существования и целостности JAR.
5. Проверка `fabric.mod.json`, Mixin JSON и mod ID.
6. Генерация SHA-256.
7. Публикация preview artifact; stable tag только после ручной проверки.

Для NovaCraft:

1. .NET build с warnings-as-errors.
2. Unit-тесты.
3. Publish Windows x64.
4. Проверка EXE.
5. Сборка Inno Setup.
6. Smoke-test install → запуск → uninstall.
7. Сохранение установщика, portable ZIP и TRX.

## 7. Проверка перед релизом

- Установка только в выбранный профиль.
- Повторная установка не перезаписывает существующий JAR.
- Неверный SHA-256 отклоняется.
- Неверные Minecraft/Fabric metadata отклоняются.
- Отключение мода не удаляет его.
- Обновление одной сборки не меняет соседние профили.
- Запуск Minecraft после установки проверяется отдельно от сборки лаунчера.
